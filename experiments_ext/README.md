# SPAR extension

This directory contains the public implementation of the support-preserving
anchored residual forecaster (SPAR) and the reviewer-requested validation code.

## Name mapping

The implementation was developed under the internal machine identifier
`saqr_point_query`. That identifier is retained in CLI choices and sanitized
historical manifests so that archived artifacts remain verifiable. It denotes
the method called **SPAR** in the paper; no alternate network name is used.

## Core files

- `support_aware_model.py`: 300 -> 96 -> 24 -> 64 -> 1 anchored residual model.
- `raw_holdout_data.py`: raw-target spatial blocking before any target gridding.
- `raw_point_supervision.py`: direct raw-observation LASSO and neural training.
- `run_raw_holdout_pilot.py`: one-tile/one-seed runner and manifest writer.
- `run_multiregion_suite.py`: sequential multi-tile runner.
- `synthetic_truth_data.py` and `run_saqr_synthetic_truth.py`: analytic known-truth tests.
- `run_lightgbm_variance_diagnostic.py`: retained LightGBM tail diagnostic.
- `analyze_saqr_results.py` and `audit_saqr_integrity.py`: aggregation and integrity checks for locally regenerated full run trees.

## Real-data example

Download the E32N34 CSV from the linked Zenodo record, then run from the
repository root:

```powershell
python .\experiments_ext\run_raw_holdout_pilot.py `
  --csv-path C:\path\to\EGMS_L3_E32N34_100km_U_2018_2022_1.csv `
  --tile E32N34 `
  --output-root .\results\_local\E32N34_seed42 `
  --cache-dir .\results\_cache `
  --seed 42 --epochs 60 --patience 12 --batch-size 16 `
  --models lasso_raw_supervised saqr_point_query
```

The runner records the command, seed, data fingerprint, baseline commit,
extension-code hashes, runtime, metrics, and prediction artifacts. Test future
targets are never used to construct a target grid.

## Analytic known-truth example

```powershell
python .\experiments_ext\run_saqr_synthetic_truth.py `
  --output-root .\results\_local\synthetic_composite_idw `
  --scenario composite --input-interpolation idw `
  --grid-size 64 --support-points 1024 --noise 0.35 `
  --seed 42 --epochs 60 --patience 12
```

Repeat with `linear` and `nearest` to reproduce the interpolation-sensitivity
comparison. Analytic future targets are evaluated from known functions and are
never generated by the interpolation operator.

## Dependencies

Use `experiments/environment.yml` or `experiments/requirements-revision.txt`.
GPU execution is recommended for neural experiments; aggregate results and
prediction artifacts are included so that the reported statistics can be
inspected without rerunning training.
